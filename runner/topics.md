# 연구 주제 (러너가 `topics.yaml`을 갱신할 때 `read_doc`으로 읽는 대본)

> **이 파일은 GPT 지침 칸에 붙여넣지 않는다.** 주제를 제안하기 직전에 `read_doc`으로 읽는다.

`topics.yaml`은 매주 새 논문을 자동 수집하는 검색 설정이다. 사람이 YAML을 손으로 쓰면
문법이 깨지고, 무엇보다 **분야를 고정하지 않는다.** 그래서 네가 만들어 Issue로 넘기고
파일은 CI가 쓴다.

## 언제 제안하나 (그 밖에는 먼저 꺼내지 마라)

- **첫 세션에서 목표가 정해졌을 때**
- **논문 한 편을 다 읽었을 때** — 방금 읽은 논문이 그 주제의 가장 좋은 씨앗이다
- 사용자가 "주제 갱신하자"고 할 때는 언제든

## ⚠️ 가장 중요 — 단어가 아니라 **분야**로 고정한다

`HBM`으로 주제를 잡았더니 high bandwidth memory가 아니라 **human breast milk** 논문이
왔다(2026-08-04, 실제 사고). 검색어를 다듬어 고칠 문제가 아니다 — 자연어 검색은 분야를
모르기 때문에 약어가 겹치는 모든 주제에서 같은 일이 난다: `MI`(motor imagery /
myocardial infarction), `CNN`, `ADC`, `SVM`, `BCI`…

**배제어를 늘리는 것은 두더지 잡기다** — 겪은 오검출만 막고 처음 보는 것은 못 막는다.
근본 해결은 하나뿐이다: **그 주제가 어느 분야인지 못 박는다.** 방법은 셋이고,
**씨앗 논문(seed)이 기본**이다.

| 방법 | 무엇을 적나 | 언제 |
|---|---|---|
| `seed` | 그 주제의 대표 논문 **DOI 1~3편** | **기본** — 사용자가 이미 읽었거나 고른 논문이 있다 |
| `topics` | OpenAlex topic id (`T12345`) | 씨앗에서 한 번 확정된 뒤 굳힐 때 |
| `field` | OpenAlex field id (`fields/22`) | 더 넓게 잡고 싶을 때 |

씨앗 DOI는 **사용자에게 물어서** 얻거나, `papers/READING_STATUS.md`·`papers/<slug>/meta.yaml`의
`link`에서 가져온다. **DOI를 지어내지 마라** — 없으면 "씨앗 논문 하나만 알려줘"라고 묻고,
끝내 없으면 `seed` 없이 제안하되 **"이 주제는 분야가 고정되지 않아 엉뚱한 논문이 섞일 수
있다"**고 사용자에게 말한다.

## 검색어 쓰는 법

- **영어로.** 논문 검색은 영어가 압도적으로 잘 걸린다.
- **약어를 단독으로 쓰지 마라.** 풀어 쓴 말과 함께: `high bandwidth memory stacked DRAM`
  (`HBM` 하나만 쓰지 않는다).
- 그 분야에서만 쓰는 **기술 용어를 2~3개** 섞는다(`through-silicon via`, `thermal throttling`).
- 주제는 **2~4개**까지. 많을수록 인박스가 읽히지 않는다.

## 제안 → 승인 → Issue

1. 사람 말로 보여준다: *"주제 2개 제안 — ① HBM(씨앗: 네가 읽은 ISSCC 2022 논문) ② …"*
2. **승인받는다.** 승인 없이 쓰지 마라.
3. `save_session`(mode: `research`, title: `topics — <한 줄 이유>`)으로 아래 형식을 보낸다.

```
## 주제

### hbm | HBM (고대역폭 메모리)
query: high bandwidth memory stacked DRAM through-silicon via
seed: 10.1109/ISSCC.2022.9731621
exclude: breast milk | lactation

### old-topic | 더 안 볼 주제
remove: true
```

- **YAML을 직접 쓰지 마라.** 위 평문만 쓰면 CI가 `topics.yaml`을 만든다.
- 적지 않은 주제는 **지워지지 않는다**(id 단위 병합) — 지우려면 `remove: true`.
- CI 회신에 분야 고정이 없는 주제가 있으면 경고가 붙는다. 그 경고를 사용자에게 그대로
  전하고 씨앗 논문을 받아 다시 제안한다.

## 인박스가 이상할 때 (다음 세션에서)

`papers/inbox.md`에 주제와 무관한 논문이 보이면 **그냥 넘기지 마라 — 그게 고칠 신호다.**
사용자에게 "이 논문은 주제와 다르다, 맞나?"를 확인하고, 맞으면 그 자리에서
① 씨앗 논문을 추가하거나 ② 검색어에 분야 용어를 더하는 `[설정]` Issue를 만든다.
배제어는 마지막 수단이다.
