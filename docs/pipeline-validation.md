# 기록 파이프라인 검증 절차

세션 → GitHub 기록 경로를 **실제로** 확인하는 절차. 템플릿의 러너 계약이나 CI를 바꾼
뒤에는 이걸 한 번 돌린다.

> **왜 필요한가**: 2026-08-04에 "세션이 끝나도 GitHub에 아무것도 안 남는다"가 보고됐다.
> 원인이 세 겹이었고 **셋 다 코드 테스트로는 안 잡혔다** — 러너가 기록을 아예 호출하지
> 않았고(지시가 관측 불가능한 시점에 걸려 있었다), 러너가 안 쓴 STATUS 절은 CI가 조용히
> 건너뛰었고, `[논문]` Issue는 워크플로 게이트를 통과하지 못했다.
> 파이프라인은 **끝에서 끝까지 실물로** 확인해야 한다. 유닛 테스트는 조각만 지킨다.

---

## 0. 준비

검증용 repo 하나를 템플릿에서 새로 만든다. 실제 학습 repo에서 하지 않는다 —
검증이 실패하면 기록이 지저분해진다.

- [ ] 템플릿에서 새 repo 생성 (`SETUP.md` 절차)
- [ ] fine-grained PAT 발급 — Contents: Read / Issues: Read and write
- [ ] Custom GPT에 `runner/action-schema.yaml` 붙여넣고 `runner/instructions.md` 적용
- [ ] Actions 탭에서 워크플로가 **활성**인지 확인 (fork/template은 기본 비활성일 수 있다)

## 1. 자동 기록 — "말 안 해도 도는가" (가장 중요)

이 항목이 이 문서의 핵심이다. 나머지가 다 맞아도 여기서 실패하면 아무것도 안 남는다.

- [ ] GPT와 학습 세션을 **평소처럼** 시작한다
- [ ] **"깃헙에 반영해" 류의 말을 절대 하지 않는다**
- [ ] 첫 응답 직후 repo의 Issues에 `[학습] …`이 열렸는가?
- [ ] 응답 끝에 `기록 중 · Issue #N`이 표시되는가?
- [ ] 두세 번 더 주고받은 뒤, 그 Issue에 코멘트가 **계속 붙는가**?
- [ ] 브라우저 탭을 그냥 닫는다 → `daily/`에 파일이 **이미** 있는가?
      (닫기 전까지 붙인 내용이 남아 있어야 한다. `closeNote`는 기록의 조건이 아니다.)

> ❌ Issue가 안 열리면: 러너 지시의 「쓰기 계약」이 적용됐는지 확인.
> 예전 지시("세션이 끝나면 반드시")가 남아 있으면 발화하지 않는다.

## 2. 노트 내용

- [ ] `daily/YYYY-MM-DD-<slug>.md` 생성됨
- [ ] 내가 한 말이 **요약되지 않고 그대로** 들어 있다
- [ ] 정규 헤딩 5개가 다 있다 — `오늘 직접 학습한 지식` · `취약 영역` ·
      `다음 복습 질문` · `현재 이해 수준` · `미해결 질문`
- [ ] Issue 코멘트에 CI 회신이 왔다 (파일 경로 · 줄 수)
- [ ] ⚠️ "자동 보정" 경고가 **없다** (있으면 러너가 그 절을 안 쓴 것 — 실패 신호다)

## 3. STATUS 승격

세션 하나만으로 확인된다.

- [ ] `STATUS.md`의 `## 지금 약한 것`이 **채워졌다** (노트의 `## 취약 영역`에서 옴)
- [ ] `## 다음 복습 질문`이 채워졌다
- [ ] `## 최근 궤적`에 `- YYYY-MM-DD · <제목> → daily/…` 한 줄이 붙었다
- [ ] 같은 Issue에 코멘트를 하나 더 달아 CI를 다시 돌린다 →
      **궤적 줄이 중복되지 않는다** (재실행 안전성)

## 4. 개념 그래프

- [ ] `concepts.json`이 생성됐다
- [ ] CI 로그에 `분야 N개`가 찍힌다
- [ ] 같은 과목이 여러 이름으로 쪼개졌다면 → `subjects.yaml`에 별칭을 적고
      Actions에서 워크플로를 다시 돌린다 → 로그에 `분야 별칭 N건을 … 합쳤다`
- [ ] 미분류가 있으면 로그에 개수가 찍힌다 (찍어 맞추지 않고 남기는 것이 정상)

## 5. 논문 트랙

- [ ] Paper GPT로 `[논문] <slug> — <섹션>` Issue를 연다
- [ ] `papers/<slug>/sessions/YYYY-MM-DD-<섹션>.md` 생성됨
- [ ] `## 정제본 갱신`을 넣었다면 `papers/<slug>/paper.md`의 해당 절이 바뀜
- [ ] `## 주석`을 넣었다면 `papers/<slug>/annotations.md`에 붙음
- [ ] `papers/READING_STATUS.md`가 생기고 `## Progress`가 갱신됨
- [ ] CI를 다시 돌려 **주석이 중복되지 않는지** 확인

## 6. 앱(Topdown)에서 보이는가

- [ ] Topdown에 repo를 연결한다
- [ ] 학습 탭 — `오늘`에 "지금 약한 것"·"복습 먼저"가 뜬다 (§3의 결과)
- [ ] 지식 그래프 — 노드가 채워져 보이고 라벨이 읽힌다
- [ ] 이어진 개념끼리 붙어 있다 (분야가 달라도)

---

## 실패했을 때

| 증상 | 먼저 볼 곳 |
|---|---|
| Issue가 안 열림 | 러너 지시의 「쓰기 계약」 — 기록이 세션 **시작**에 걸려 있는가 |
| Issue는 열리는데 파일이 없음 | Actions 탭 — 워크플로 활성 여부, 실행 로그 |
| 파일은 생기는데 STATUS가 빔 | 노트에 `## 취약 영역`이 있는가 (없으면 승격할 원본이 없다) |
| `[논문]`이 무시됨 | 워크플로 게이트에 `[논문]`이 있는가 |
| 분야가 잘게 쪼개짐 | `subjects.yaml` 별칭 — 없으면 정규화하지 않는다(안전 기본값) |
| 그래프가 비어 보임 | CI 로그의 `개념 N` — 0이면 `## 개념 지도`가 노트에 없는 것 |

## 코드 테스트 (파이프라인 검증의 대체물이 아니다)

```
python3 scripts/test_ingest_learning_note.py
python3 scripts/test_build_concepts.py
```

이건 조각을 지킬 뿐이다. **위 §1은 사람이 직접 해야 한다** — "러너가 스스로 기록을
호출하는가"는 코드로 확인할 수 없다.
